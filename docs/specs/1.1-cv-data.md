# 1.1. Модель данных резюме

**Статус:** done
**Зависит от:** 0.3
**Ветка:** `step/1.1-cv-data`

## Цель
Единый типизированный источник данных резюме для обеих локалей. Из него потом строятся
блоки в чате (2.4–2.5), системный промпт агента (3.1), страница `/cv` и JSON-LD (6.1).
После шага данные можно получить одним вызовом `getCv('ru')`, и они гарантированно валидны.

## Входит
- Zod-схема резюме, тип `Cv` выводится из неё.
- Данные: общая часть (не зависит от языка) + тексты EN и RU.
- `getCv(locale)` собирает полное резюме и валидирует его.
- Хелперы длительности: стаж в месяцах для позиции и общий стаж.
- Unit-тесты.

## Не входит
- Любой UI → шаги 1.2, 2.4, 2.5
- Сериализация для промпта агента → шаг 3.1 (там станет понятно, какой формат нужен)
- Фото и PDF-файлы: в схеме есть пути, сами файлы добавляет владелец (до шагов 2.4 / 2.3)
- Финальные тексты резюме — их пишет владелец (см. вопрос 2)

## Ключевые решения и интерфейсы

### Почему данные разделены на common + тексты по локали
Даты, компании, стек, контакты одинаковы в обоих языках. Если хранить два полных резюме, рано или
поздно в одном поправят дату и забудут во втором. Поэтому:
- `common.ts` — факты: id позиций, компании, даты, стек, контакты, навыки;
- `en.ts` / `ru.ts` — только тексты, привязанные к тем же id;
- `getCv(locale)` склеивает их по id. Тест проверяет, что у каждого id есть тексты в обеих локалях.

### Схема (сокращённо)
```ts
// 'YYYY-MM', например '2024-10'
const YearMonth = z.string().regex(/^\d{4}-(0[1-9]|1[0-2])$/)

const CvCommon = z.object({
  person: z.object({
    name: z.object({ en: z.string(), ru: z.string() }),     // Alexandr Kozikov / Александр Козиков
    photo: z.string(),                                     // путь в public, например '/cv/photo.webp'
    timezone: z.string(),                                  // 'GMT+3', город и страну не указываем
    openTo: z.array(z.enum(['remote', 'hybrid', 'office', 'relocation'])),
  }),
  contacts: z.object({
    email: z.email(),
    telegram: z.url(),
    linkedin: z.url(),
    github: z.url(),
    site: z.url(),
  }),
  files: z.object({ pdf: z.object({ en: z.string(), ru: z.string() }) }),
  experience: z.array(z.object({
    id: z.string(),                // 'orion-soft'
    company: z.string(),
    url: z.url().optional(),
    start: YearMonth,
    end: YearMonth.nullable(),     // null = по настоящее время
    stack: z.array(z.string()),
  })),
  education: z.array(z.object({ id: z.string(), start: z.number().int(), end: z.number().int() })),
  skills: z.array(z.object({
    id: z.string(),                // 'main', 'backend', 'ai'…
    items: z.array(z.object({
      name: z.string(),
      aliases: z.array(z.string()).default([]),   // 'Vue.js', 'VueJS' → 'Vue' — для сравнения с вакансией в 5.4
      main: z.boolean().default(false),           // выделяется в UI
    })),
  })),
  updatedAt: YearMonth,
})

const CvTexts = z.object({
  title: z.string(),               // 'Fullstack Engineer'
  about: z.array(z.string()),      // абзацы
  experience: z.record(z.string(), z.object({
    role: z.string(),
    summary: z.string(),
    highlights: z.array(z.string()),
  })),
  education: z.record(z.string(), z.object({ degree: z.string(), institution: z.string() })),
  skillGroups: z.record(z.string(), z.string()),   // id группы → название
  languages: z.array(z.object({ name: z.string(), level: z.string() })),
})
```

`Cv` (результат `getCv`) — плоский удобный объект: `person.name` уже строка нужного языка,
у позиций опыта `role` / `summary` / `highlights` уже подставлены, и так далее. Компоненты
и промпт работают только с `Cv` и не знают про разделение на common и тексты.

### API
```ts
export type Locale = 'en' | 'ru'
export function getCv(locale: Locale): Cv                 // бросает ошибку, если данные невалидны
export function monthsBetween(start: string, end: string | null, now?: Date): number
export function getTotalExperienceMonths(cv: Cv, now?: Date): number
```
- Стаж **вычисляется из дат**, а не хранится строкой «5+ years»: обновится сам, когда пройдёт время.
  `now` передаётся аргументом, чтобы тесты не зависели от текущей даты.
- Месяцы считаются включительно: `2024-10 … 2024-12` = 3 месяца.
- Общий стаж — объединение интервалов, а не сумма: пересекающиеся позиции не считаются дважды.
- Форматирование («2 года 3 мес.», «2 yr 3 mo») — не здесь, это UI (шаг 2.5, через i18n).
- Валидация через `CvSchema.parse` выполняется при первом вызове `getCv` для локали, результат кешируется.

### Наполнение
- `common.ts` и `en.ts` — из текущего PDF-резюме.
- `title` — `Fullstack Engineer`, как договорились (§7 ARCHITECTURE). Остальные тексты переносятся
  из PDF как есть, а переписать их под fullstack — задача владельца.
- `ru.ts` — черновой перевод EN, владелец заменит своим текстом.
- Контакты — из ответа на вопрос 1.
- Локации нет: только таймзона `GMT+3` и форматы работы `openTo` (UI склеит, например, «Remote · GMT+3»).
