# F2. Резюме в чате

**Статус:** done
**Зависит от:** F1
**Ветка:** `step/F2-cv-in-chat`

## Цель
Кнопки «Показать резюме» и «Скачать резюме» перестают быть заглушками: ассистент без LLM отвечает
блоками резюме (Hero, About, Experience, Education, Skills) и карточкой скачивания PDF. Блоки —
презентационные компоненты с данными через props, их же переиспользуют tool `showCvSection` (F3)
и страница `/cv` (F7).

## Входит
- Компоненты в `app/components/blocks/`:
  - `CvHero` — фото, имя, должность, стаж (считается из дат), часовой пояс, форматы работы,
    кнопки контактов.
  - `CvAbout` — абзацы «О себе».
  - `CvExperience` — таймлайн: компания (ссылка, если есть `url`), роль, период и длительность,
    summary, highlights, чипы стека.
  - `CvEducation` — степень, вуз, годы и подраздел «Языки».
  - `CvSkills` — группы навыков, `main` выделены.
  - `DownloadCard` — PDF текущего языка и дата обновления резюме.
- Data-части `data-cv` и `data-download` в `CvUIMessage`, записи в реестре блоков, zod-схемы этих
  частей для проверки истории из localStorage.
- Сценарии `showCv()` / `downloadCv()` в `useLocalScenarios` (как в ARCHITECTURE §6), обработчики
  в `useQuickActions` вызывают их.
- Поэтапное появление блоков с учётом `prefers-reduced-motion`.
- Форматирование стажа и периодов через i18n, правила множественного числа для русского.
- shadcn: `avatar` (фото с фолбэком на инициалы), `badge` (чипы стека, навыков, форматов работы).
- Тесты (см. «Как проверить»).

## Не входит
- `/api/chat`, tool `showCvSection` → F3. Страница `/cv`, JSON-LD → F7.
- `public/cv/photo.webp` и RU-PDF — их добавит владелец (поведение без них — ниже).
- Генерация PDF из данных (бэклог), сворачивание длинных секций, печатная вёрстка.

## Ключевые решения

### Часть хранит ссылку на секцию, а не данные
`data-cv` = `{ section: 'hero' | 'about' | 'experience' | 'education' | 'skills' }`,
`data-download` = `{}`. Обёртка `CvSectionBlock` (запись реестра для `data-cv`) берёт данные из
`useCv()` и передаёт в нужный `Cv*`-компонент срез через props. Поэтому:
- смена языка перерисовывает уже показанное резюме на новом языке;
- в localStorage лежат несколько байт, а не копия резюме; после обновления данных старая история
  показывает актуальное резюме;
- `Cv*`-компоненты ничего не знают о чате и i18n-локали резюме — F3 и F7 подключают их так же.

Одно assistant-сообщение «Показать резюме» содержит 5 частей `data-cv` по порядку, без
вводного текста. «Скачать резюме» — только `DownloadCard`, тоже без текста. Неизвестная `section` в истории не проходит валидацию → история
сбрасывается, как при битом JSON (версию истории поднимать не нужно: новые части лишь
расширяют формат).

### Поэтапное появление
Сообщение добавляется целиком, а появление делает CSS: каждый блок плавно проявляется со
сдвигом ~8 px, задержка ~120 мс × индекс части. Без таймеров и промежуточных состояний — в
историю ничего «недопоказанного» не попадает. Анимация только для сообщений, созданных в этом
визите (id в `useState`), восстановленная история показывается сразу. `motion-reduce` — без
анимации.

Прокрутка: ответ с блоками **не прокручивается автоматически**. Список прокручивается только
до вопроса пользователя (он виден над полем ввода), блоки появляются ниже, за краем видимой
области, и пользователь листает сам. Сейчас F1 после сообщения пользователя прыгает в самый низ
и следит за ростом контента — для локальных блочных ответов это отключается (сообщение
добавляется после прокрутки, и «прилипание к низу» на него не срабатывает).

### Стаж и периоды
- Стаж в Hero: `getTotalExperienceMonths` (пересечения не суммируются) → целые годы вниз:
  «5+ лет опыта» / «5+ years of experience».
- Период в Experience: «окт 2024 — н.в.» через `Intl.DateTimeFormat` текущей локали, длительность
  коротко: «2 г. 3 мес.» / «2 yrs 3 mos» (обе границы включительно, как в `monthsBetween`).
- Сейчас у vue-i18n нет правил множественного числа для русского (по умолчанию английские) —
  добавляю `pluralRules.ru` на `Intl.PluralRules`. Чистая функция форматирования длительности —
  в `shared/cv`, с unit-тестами.
- Чат рендерится только на клиенте (история после гидратации), так что расхождения «текущего
  месяца» между сервером и клиентом нет.

### Контакты в Hero
Список ссылок из `ContactLinks` выносится в общий композабл, его используют и TopBar (иконки),
и Hero (кнопки с подписями: Telegram, LinkedIn, GitHub, Email). Hero — самодостаточная карточка,
на `/cv` TopBar-контактов рядом может не оказаться.

### Скачивание и отсутствующие файлы
- `downloadCv()` добавляет пару сообщений с `DownloadCard` и сразу скачивает PDF текущей локали
  (`<a download>` программно). В карточке — имя файла, дата `updatedAt` из данных резюме и кнопка
  «Скачать» для повторного скачивания. Только текущий язык, размера нет, сетевых запросов нет.
- EN-PDF — файл от владельца (`Alexandr_Kozikov_en.pdf`), кладётся в
  `public/cv/Alexandr_Kozikov_en.pdf`. Пока RU-PDF нет, `files.pdf.ru` в данных указывает на
  EN-файл; когда владелец добавит RU-версию, меняется одна строка.
- Фото: `Avatar` с фолбэком на инициалы — без `photo.webp` вёрстка не ломается.
- Известное ограничение: iOS Safari открывает PDF во вкладке вместо скачивания; кнопки в
  карточке остаются запасным путём.

### Вид блоков
Ответ ассистента и так во всю ширину. Каждая секция — карточка с заголовком `h3` (кроме Hero) в
токенах темы; отдельный shadcn `card` не нужен, хватит своего класса. На 375 px Hero
перестраивается в колонку, чипы переносятся.

## Как проверить
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` — зелёные
- [ ] «Показать резюме»: вопрос виден над полем ввода, 5 блоков появляются ниже по очереди,
      список сам не прокручивается
- [ ] Включён reduce motion в ОС — блоки появляются сразу
- [ ] Перезагрузка — резюме на месте, без анимации; смена языка — блоки на новом языке
- [ ] Стаж и длительности верные, русские формы: 1 год / 2 года / 5 лет, 1 месяц / 3 месяца
- [ ] Компания с `url` — ссылка в новой вкладке; `main`-навыки выделены
- [ ] «Скачать резюме»: скачивается PDF текущего языка (на RU пока EN-файл), в карточке дата,
      кнопка качает ещё раз
- [ ] Без фото — инициалы; ошибок в консоли нет
- [ ] 375 px и обе темы: без горизонтального скролла, читаемо
- [ ] Тесты: форматирование длительности/стажа (en, ru); `showCv` добавляет сообщение с 5
      частями и блоки рендерятся; `downloadCv` добавляет карточку и запускает скачивание; история с
      неизвестной `section` сбрасывается

## Открытые вопросы
1. **DownloadCard: оба языка или только текущий?** Предлагаю оба, текущий — основная кнопка
   (ARCHITECTURE §3.2 говорит «EN/RU PDF»).
   - **Ответ:** только текущий язык.
2. **Языки (`languages`) — где показать?** В F2 их нет в списке блоков. Предлагаю добавить
   подраздел «Языки» в `CvEducation`, без отдельного блока.
   - **Ответ:** в `CvEducation`.
3. **Размер файла через `HEAD`** (предлагаю: заодно проверяем, что файл есть) или убрать размер
   из карточки и не делать запрос?
   - **Ответ:** убрать размер, без `HEAD`.
4. **Пока PDF нет** — карточка «Файл скоро появится» (предлагаю) или заглушки-PDF в `public/cv/`,
   которые владелец потом заменит?
   - **Ответ:** берём EN-PDF от владельца; RU пока ссылается на него.
5. **Прокрутка к началу ответа** для блочных ответов (предлагаю) или как в F1 — в самый низ?
   - **Ответ:** не прокручивать автоматически: ответ выводится ниже, за краем видимой области.
6. **Вводный текст** перед блоками («Вот резюме кандидата:») — предлагаю без него, Hero говорит
   сам за себя. Для «Скачать резюме» — тоже только карточка.
   - **Ответ:** без вводного текста.

## Дополнение (после реализации)
- Длительность — полными словами через `Intl.NumberFormat` (`2 года 3 месяца` / `2 years 3 months`),
  а не сокращениями из i18n: Intl сам склоняет, а короткая русская форма у него «5 л.». Месяц —
  `Intl.DateTimeFormat`: «окт. 2024 г.» / «Oct 2024».
- Правила множественного числа для русского (`i18n/i18n.config.ts`) нужны только для «N+ лет опыта».
- Анимация появления применяется ко всем локальным ответам этого визита, включая текстовые
  заглушки F1.
- Пока нет `public/cv/photo.webp`, в консоли браузера 404 на фото (вёрстка не ломается — инициалы).
- По ревью: чат прокручивается **скроллом страницы**, а не внутренним контейнером. TopBar и блок
  ввода (чипы + поле) закреплены (`sticky`), над полем ввода — мягкое затухание контента.
  Автопрокрутка и «вопрос над полем ввода» работают через `window` с учётом высоты блока ввода.
