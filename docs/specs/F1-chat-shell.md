# F1. Чат-оболочка

**Статус:** done
**Зависит от:** 1.2
**Ветка:** `step/F1-chat-shell`

## Цель
Вместо заглушки «Здесь будет чат» — рабочий интерфейс чата: welcome-экран с быстрыми кнопками,
список сообщений, поле ввода, «Новый чат», история в браузере и окно «О проекте». Сервера и LLM
пока нет: ответы — локальные заглушки, но сообщения уже живут в модели `UIMessage` из AI SDK и
рендерятся через реестр блоков, так что F2–F5 только добавляют блоки и меняют транспорт.

## Входит
- Пакеты `ai@7` и `@ai-sdk/vue@4` (актуальные на 2026-10-29: 7.0.156 / 4.0.156).
- Тип сообщения `CvUIMessage` в `shared/types/chat.ts` (`UIMessage<Metadata, DataParts, Tools>`;
  в F1 data-частей и tools ещё нет, типы готовы к расширению).
- Реестр блоков `app/lib/block-registry.ts`: `part.type` → компонент. В F1 зарегистрирован только
  `text` (обычный текст с переносами строк, Markdown — в F3).
- Компоненты `chat/`: `ChatShell`, `WelcomeScreen`, `QuickActions`, `MessageList`, `MessageItem`,
  `MessagePart`, `ChatInput`, `TypingIndicator`.
- Композаблы: `useCvChat` (экземпляр `Chat` + транспорт-заглушка), `useChatPersistence`
  (localStorage), `useQuickActions` (обработчики кнопок, в F1 — заглушки).
- `ChatInput`: textarea с авто-ростом, Enter / Shift+Enter, кнопка отправки, скрепка
  (`accept=".pdf,.docx,.md,.txt"`).
- Welcome-экран: короткое приветствие (имя и роль из `useCv`) и 4 быстрые кнопки:
  «Показать резюме», «Кого вы ищете?», «Скачать резюме», «Загрузить вакансию».
- В TopBar справа: кнопка «Новый чат» и `InfoDialog` «О проекте» (последней).
- shadcn-компоненты: `dialog`, `textarea`.
- Инфраструктура компонентных тестов и первые тесты (см. ниже).

## Не входит
- Любые запросы к серверу, `/api/chat`, LLM, Markdown, кнопка stop, ошибки и повтор → F3.
- Блоки резюме, настоящие «Показать / Скачать резюме» → F2.
- Настоящие «Кого вы ищете?» → F4, загрузка и разбор файла, drag & drop → F5.
- Кнопка «вниз» при прокрутке истории, лимит длины ввода (серверные лимиты — F3).
- Синхронизация истории между вкладками (последняя запись побеждает).

## Ключевые решения

### `Chat` из AI SDK уже сейчас, транспорт — заглушка
`@ai-sdk/vue@4` экспортирует класс `Chat` и `useChat`. Берём `Chat` с собственным
`ChatTransport`, который без сети возвращает короткий поток с текстом «AI-ассистент подключится
совсем скоро» (на текущем языке, задержка ~600 мс, чтобы было видно `TypingIndicator`). Так в F1
работает весь реальный цикл: `sendMessage` → `status: submitted → streaming → ready` →
`messages`. В F3 заглушка меняется на `DefaultChatTransport({ api: '/api/chat' })`, остальной
код не трогается.

Один `Chat` на экземпляр Nuxt-приложения (через `nuxtApp`, а не модульная переменная), чтобы
на сервере состояние не делилось между запросами. Его видят и `ChatShell`, и кнопка «Новый чат»
в TopBar. Смена языка (`/` ↔ `/ru`) чат не пересоздаёт.

### Быстрые кнопки и скрепка в F1
Каждое действие добавляет в `chat.messages` user-сообщение (текст кнопки или имя файла) и
assistant-сообщение «Эта функция появится скоро» — локально, без транспорта. Скрепка и «Загрузить
вакансию» открывают выбор файла; выбранный файл никуда не отправляется. Обработчики собраны в
`useQuickActions`, в F2–F5 меняются только их тела.

Welcome-экран показывается, пока сообщений нет. После первого сообщения кнопки становятся
компактными чипами над полем ввода (на мобильном — одна строка с горизонтальной прокруткой).

### Реестр блоков
`Record<type, Component>`; `MessagePart` берёт компонент по `part.type`. Неизвестный тип не
рендерится, в dev — `console.warn`. Части `step-start` и т.п. из AI SDK просто пропускаются.
Новый блок = компонент + строка в реестре + тип в `CvUIMessage`.

### Список сообщений
- Пользователь справа (пузырь), ассистент слева (без пузыря, во всю ширину — блоки резюме будут
  широкими).
- Автопрокрутка вниз при новом сообщении и во время стрима, **только если пользователь уже внизу**
  (порог ~80 px). После собственной отправки — прокрутка вниз всегда.
- `role="log"` + `aria-live="polite"` для читалок экрана.

### Поле ввода
- Авто-рост через `useTextareaAutosize` из VueUse (уже в зависимостях), максимум ~8 строк, дальше
  прокрутка внутри. CSS `field-sizing: content` не берём — поддержка браузерами неполная.
- Enter — отправить, Shift+Enter — перенос. Во время IME-ввода (`isComposing`) Enter не отправляет.
- Отправка недоступна при пустом тексте и пока ассистент отвечает. Фокус возвращается в поле.

### История в localStorage
- Ключ `cv-chat`, значение `{ version: 1, messages }`. Сохраняем, когда `status` вернулся в
  `ready` (не на каждый токен), храним последние 100 сообщений.
- Чтение при монтировании: битый JSON, другая `version` или не прошедшие
  `safeValidateUIMessages` из `ai` сообщения → ключ удаляется, чат пустой.
- Ошибки `localStorage` (приватный режим, переполнение) глотаем — чат работает без истории.
- «Новый чат» очищает сообщения и ключ, возвращает welcome-экран. Кнопка неактивна, пока чат пуст.
  Подтверждения нет (см. вопрос 3).

### SSR
Сервер рендерит welcome-экран (быстрая первая отрисовка, текст виден поисковикам). История
восстанавливается в `onMounted`: у вернувшегося пользователя welcome на мгновение сменится
историей (см. вопрос 2).

### InfoDialog «О проекте»
Иконка `Info` справа в TopBar, shadcn `Dialog`. Текст через i18n: что это за сайт; как он
устроен (Nuxt, Vercel AI SDK, OpenRouter, генеративный UI); приватность — история хранится только
в браузере, на сервер уходит лишь то, что нужно для ответа, файлы не сохраняются; ссылка на
исходники (см. вопрос 4).

### Компонентные тесты
- Добавить `happy-dom` и `@vue/test-utils`; `@nuxt/test-utils` уже стоит.
- Vitest с двумя проектами: `unit` (окружение `node`, `tests/unit`, как сейчас) и `nuxt`
  (окружение `nuxt` + happy-dom, `tests/nuxt`). `pnpm test` гоняет оба. В `CLAUDE.md` дописать
  про `tests/nuxt`.
- Тесты: реестр (известный / неизвестный тип); `ChatInput` (Enter, Shift+Enter, пустой ввод);
  персистентность (сохранение, другая версия, битый JSON); welcome ↔ список; «Новый чат» очищает
  историю; быстрая кнопка добавляет пару сообщений.

## Как проверить
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` — зелёные
- [ ] Пустой чат: приветствие и 4 кнопки; каждая кнопка добавляет вопрос и ответ-заглушку,
      кнопки уходят в чипы над полем ввода
- [ ] Текст: Enter отправляет, Shift+Enter переносит строку, поле растёт до ~8 строк;
      видна «печатает…», затем ответ-заглушка; пустое сообщение не отправляется
- [ ] Скрепка открывает выбор файла только pdf/docx/md/txt
- [ ] Длинная переписка: автопрокрутка вниз; если прокрутить вверх — новый ответ не дёргает
- [ ] Перезагрузка страницы — история на месте; «Новый чат» — пусто, после перезагрузки тоже
- [ ] Подменить в localStorage версию или испортить JSON — чат открывается пустым, без ошибок
- [ ] Смена языка посреди диалога: UI переведён, история на месте
- [ ] InfoDialog открывается, закрывается по Esc и крестику, фокус возвращается на кнопку
- [ ] 375 px: TopBar в одну строку, поле ввода внизу, без горизонтального скролла; обе темы
- [ ] Нет hydration-warnings в консоли

## Открытые вопросы
1. **Свободный текст в F1** — отвечать заглушкой через транспорт-заглушку (предлагаю: проверяем
   весь цикл `Chat` уже сейчас) или заблокировать поле ввода до F3?
   - **Ответ:** отвечаем заглушкой через транспорт-заглушку.
2. **Мигание при восстановлении истории** — SSR-рендер welcome и замена историей после монтирования
   (предлагаю: быстрый первый экран и текст для поисковиков, мигание только у вернувшихся) или
   рендерить чат только на клиенте со скелетоном (без мигания, но пустой первый кадр)?
   - **Ответ:** SSR-рендер welcome, история после монтирования.
3. **«Новый чат» без подтверждения** (предлагаю: потеря истории не критична) или с диалогом
   «Начать заново?»
   - **Ответ:** без подтверждения.
4. **InfoDialog** — репозиторий публичный, ставим ссылку на GitHub? Текст «О проекте» пишу я по
   описанию выше, владелец правит в `en.json` / `ru.json` — подходит?
   - **Ответ:** репозиторий публичный — ссылка на GitHub есть; текст пишет исполнитель, владелец правит.
5. **Кнопка «Новый чат»** — иконка `SquarePen` с tooltip, как в ChatGPT/Claude (предлагаю,
   экономит место на мобильном), или иконка + подпись на десктопе?
   - **Ответ:** иконка `SquarePen` с tooltip.

## Дополнение (после ревью)
- «Новый чат» заменён на **«Сбросить чат»**: иконка `RotateCcw`, tooltip «Сбросить чат» / «Reset chat».
  Поведение то же — останавливает ответ, очищает сообщения и историю в localStorage.
- **Welcome-экран убран.** Приветствие — первое сообщение ассистента (`ChatGreeting`) с эффектом
  печати; под ним после печати появляются 4 карточки быстрых действий, после первого сообщения
  они уходят в чипы над полем ввода.
  - Приветствие не входит в историю: не хранится в localStorage и не уйдёт в модель (F3).
  - Печатается один раз за визит и только в пустой чат: флаг в `useState`, поэтому смена языка и
    сброс чата не перезапускают анимацию. При восстановленной истории и при
    `prefers-reduced-motion` текст показывается сразу.
  - Сервер рендерит весь текст, ещё не напечатанная часть — `invisible`: вёрстка не прыгает,
    текст есть в HTML и в `aria-label` для читалок экрана.
- Реализационные отличия от спеки: `useChat` вместо устаревшего класса `Chat` (класс не
  перерисовывал часть, в которую идёт стрим); история восстанавливается в плагине после
  гидратации, а не в `onMounted`; прокрутка вниз срабатывает на любое новое сообщение
  пользователя, включая быстрые кнопки.
