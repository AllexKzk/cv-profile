# 0.3. i18n, CLAUDE.md, env и первый деплой

**Статус:** review
**Зависит от:** 0.2
**Ветка:** `step/0.3-i18n-docs-deploy`

## Цель
Закрыть фундамент. После шага:
- все строки интерфейса берутся из словарей EN и RU;
- у исполнителей есть `CLAUDE.md` с правилами проекта;
- переменные окружения описаны;
- сайт открывается на Vercel, и каждая ветка шага получает свой preview-URL для ревью.

## Входит

### i18n
- Модуль `@nuxtjs/i18n` (10.x), локали `en` (по умолчанию) и `ru`, словари в `i18n/locales/{en,ru}.json`.
- Стратегия URL `prefix_except_default`: английская версия на `/`, русская на `/ru`.
- Язык браузера определяется **только на корне и только при первом визите**. Выбор сохраняется
  в cookie `cv-locale`, и дальше редиректов нет.
- SEO-базис от модуля: `<html lang>`, `hreflang`-ссылки (через `useLocaleHead`) — нужно для SEO
  в шаге 6.1.
- Демо-страница переводится на `$t(...)`, плюс временная кнопка EN/RU. Её, как и кнопку темы,
  заменит TopBar в шаге 1.2.

### CLAUDE.md
Короткий файл (до ~80 строк), который исполнитель читает в начале каждой сессии:
- **Процесс:** спека → утверждение → код в `step/*`, делать только то, что в спеке, отчёт в конце (ссылка на `docs/PLAN.md`).
- **Стек и структура папок** (ссылка на `docs/ARCHITECTURE.md`, без копирования).
- **Команды:** `dev`, `lint`, `typecheck`, `test`, `build`. Перед отчётом все должны быть зелёными.
- **Конвенции:**
  - `<script setup lang="ts">`, Composition API;
  - компоненты в PascalCase;
  - все строки UI только через i18n, обе локали сразу;
  - стили только токенами (`bg-background`, а не `bg-white`);
  - иконки из `@lucide/vue`.
- **Ловушки, на которые уже наступили:**
  - `shadcn-vue add` может вписать `@import` Google Fonts в `main.css` — проверять дифф и удалять;
  - `lucide-vue-next` устарел, используем `@lucide/vue`;
  - TypeScript закреплён на 5.9: typescript-eslint не поддерживает 7.x.
- **Секреты:** только в серверном `runtimeConfig`, никогда в `public` и никогда в коде.

### Env
- `.env.example` со всеми ключами из ARCHITECTURE §4 и пустыми значениями, у каждого комментарий,
  в каком шаге он понадобится.
- В `nuxt.config.ts` объявляется `runtimeConfig` с пустыми значениями по умолчанию: Nuxt
  подставляет `NUXT_*` переменные в рантайме только для ключей, объявленных в конфиге.
  ```ts
  runtimeConfig: {
    openrouterApiKey: '',        // NUXT_OPENROUTER_API_KEY
    openrouterModel: '',         // NUXT_OPENROUTER_MODEL
    openrouterFallbackModels: '',
    upstashRedisRestUrl: '',
    upstashRedisRestToken: '',
    dailyLlmLimit: 500,
    telegramBotToken: '',
    telegramChatId: '',
    public: {
      siteUrl: '',               // NUXT_PUBLIC_SITE_URL
    },
  },
  ```
  > В ARCHITECTURE §4 ключи OpenRouter и Upstash записаны без префикса `NUXT_`. В этом шаге
  > имена приводятся к `NUXT_*`, чтобы Nuxt подхватывал их сам, и ARCHITECTURE обновляется.

### Деплой (Vercel)
Схема: GitHub-репозиторий + Git-интеграция Vercel. Каждый пуш в `step/*` даёт preview-деплой
со своим URL, а `main` уходит в production. Ревью можно делать на живом сайте, а не только по диффу.

| Действие | Кто |
|---|---|
| Создать репозиторий на GitHub (`gh repo create`) и запушить `main` | исполнитель, **после вашего «да»** (см. вопрос 1) |
| Импортировать репозиторий в Vercel (New Project → выбрать репо, всё по умолчанию) | **вы** — это вход в аккаунт и выдача доступов |
| Проверить, что Vercel сам определил Nuxt и Node 24 | исполнитель по логам сборки (`vercel inspect` / ссылка от вас) |
| Подключить домен `allexkzk.dev` | **не в этом шаге** (вопрос 3) |

Секретов на этом шаге нет: ключи OpenRouter / Upstash / Telegram добавляются в Vercel в тех шагах,
где они понадобятся.

## Ключевые решения и интерфейсы

```ts
i18n: {
  defaultLocale: 'en',
  strategy: 'prefix_except_default',
  locales: [
    { code: 'en', language: 'en-US', name: 'English', file: 'en.json' },
    { code: 'ru', language: 'ru-RU', name: 'Русский', file: 'ru.json' },
  ],
  detectBrowserLanguage: {
    useCookie: true,
    cookieKey: 'cv-locale',
    redirectOn: 'root',
  },
  baseUrl: '',   // заполняется из NUXT_PUBLIC_SITE_URL в 6.1, нужен для абсолютных hreflang
},
```

**Почему `prefix_except_default`, а не cookie-only.** У русской версии свой URL (`/ru`), поэтому
её индексируют поисковики и можно отправить ссылку рекрутеру сразу на нужном языке.

**Тест ключей словарей.** Главная ошибка i18n — ключ есть в одном словаре и забыт в другом.
Тест сравнивает плоские списки ключей и падает с понятным списком отсутствующих.

## Как проверить
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` — зелёные
- [ ] `/` — английский, `/ru` — русский, у `<html>` правильный `lang`, в `<head>` есть `hreflang` для обеих версий
- [ ] Первый визит на `/` с русским браузером → редирект на `/ru`. После ручного переключения на EN
  редиректа больше нет (cookie)
- [ ] Кнопка EN/RU меняет язык без перезагрузки страницы, тема при этом сохраняется
- [ ] `CLAUDE.md` и `.env.example` на месте, в `.env.example` нет реальных значений
- [ ] Production-деплой на Vercel открывается, `/ru` работает. Preview-URL ветки `step/0.3-…` открывается
